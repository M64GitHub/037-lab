## What this is

**0 3 7 — music theory lab for tracker people.** A single-file browser app (`037-lab.html`) that teaches music theory in semitones (never staff notation) for chiptune/tracker musicians, and answers the question in its name: the tracker arp formula `0 3 7` is *not* the chord for every scale degree. Everything — CSS, markup, JS, and all the prose content — lives in that one file. Five tabs: Scale & Chords, Melody Lab, Ear, Techniques, Theory.

## Commands

There is no build, lint, or test step. Open `037-lab.html` directly in a browser (`open 037-lab.html`) and reload after edits. The only network dependency is the JetBrains Mono Google Font; everything else works offline via `file://`.

Audio requires a user gesture to start — the first click on anything audible creates the `AudioContext`. When checking audio changes, click a key/button rather than expecting sound on load.

For automated checks, copy the file to a scratch directory, append a `<script>` before `</body>` that exercises functions and writes results into a `<pre>`, and run headless Chrome with `--dump-dom` (`"/Applications/Google Chrome.app/Contents/MacOS/Google Chrome" --headless=new --disable-gpu --virtual-time-budget=4000 --dump-dom file:///…`). Stub `voice`, `playArp`, `audio` and `stopAll` on `window` to record the schedule instead of making sound; `--screenshot --window-size=W,H` gives a visual check (Firefox: `--headless --screenshot=… --profile <scratch dir>`, results must be visible on the page). Pure arithmetic (parsers, codecs) can also be pasted into a scratch `.mjs` and run with node.

## Layout of the file

`<style>` (lines ~10–300) → markup with a sticky header holding the **global controls** (root, scale, waveform, arp rate, volume, MIDI button) and five `<section class="tab">`s (`tab-scales`, `tab-melody`, `tab-ear`, `tab-tech`, `tab-theory`) → one `<script>` divided by `/* ===== name ===== */` banners in this order: data, state, audio, tabs, global controls, keyboard, chord chips + degree cards, progressions, finder, melody lab, url state + undo, import, harmonize, ear trainer, demos, techniques content, theory content, learn renderer, init.

Add new code inside the matching banner section; the init block at the bottom fixes the render order (read state → `fillGlobal` → `renderScaleTab` → `fillMelodyProg` → apply melody state → learn cards → restore or generate the pattern).

## Architecture

### Everything is a semitone offset
Pitches are MIDI numbers; scales, chords and intervals are arrays of semitone offsets (`iv`). `tname(midi)` formats tracker-style names (`C-4`, `A#3`); `pcname(pc)` the pitch class. `NOTE_NAMES` are sharps only. Colour language: cyan = action, amber = adjusted to fit the scale, red = outside the scale, faint = holds and rests.

### Data tables drive the UI
- `SCALES` — `iv` offsets (5–8 notes), a `group` (rendered as an `<optgroup>` in the header select, in first-appearance order) and a `mood` string shown as the tab hint. Nothing may assume seven notes: use `S.scale.iv.length` (L), `romanFor` falls back to numbers, chord stacking wraps with `% L`, the cadence picks the scale note nearest a perfect fifth (whole tone has none), 7th-chord harmonize candidates exist only when L === 7.
- `CHORDS` — `iv` is the raw tracker formula; `deg` is *which scale steps the chord stacks* (0-based). `deg` is what makes snapping work for any scale length. `sfx` is the chord-symbol suffix; `SFX` (progression syntax → id) and `SFX_OF` (id → suffix token) map both ways.
- `PROGS` — preset progressions as 0-based scale degrees (`degs`); they only fill the progression text field (`presetText`). The live progression is the typed text (see *Progressions* below).
- `DRUMS` / `DRUM_PATS` / `DRUM_FILLS` — the noise kit and its patterns (see *Drums column*).
- `COLS` — the pattern columns of the Melody Lab (see *Columns*).
- `EAR_MODES` / `EAR_SETS` / `EAR_OPTS` — the ear trainer (see *Ear trainer*).
- `TECH` / `THEORY` — `{t: title, b: HTML body, d?: DEMOS key}`; rendered as collapsible cards by `renderLearn`. A `d` key adds a "Hear it" button that calls `DEMOS[d]()`. Bodies are template strings and may call table helpers (`intervalTable()`, `fifthsTable()`), which run once at load. `INTERVALS` is the semitone → name/character table behind the interval chips and the ear trainer labels.

### `fitChord()` is the core idea
`fitChord(degIdx, chord, snap)` builds a chord on a scale degree. With `snap=true` it stacks by `chord.deg` through the scale (diatonic result); with `snap=false` it uses the raw `chord.iv`. It returns `rel` (the numbers to type in a tracker), `adj` (digit differs from the raw formula → rendered **amber**), `out` (pitch class not in scale → rendered **red**), `midis`, and `rootNote`. The degree cards, progressions, and melody lab chords all go through it. Progressions and the melody lab always pass `snap=true` with a triad, so they are always diatonic.

`fitChordRaw(rootAbs, chord)` is its sibling for chords that must not snap (borrowed chords, forced qualities): raw `iv` on an absolute root, `adj` all false, `out` per note. Both return the same shape, so everything downstream takes either.

`rootMidi()` places the root around C3–B3 but shifts C/C#/D up an octave so chords sit in a comfortable register for all 12 keys. Roman numerals (`romanFor`) only apply to 7-note scales. `invert(midis, n)` rotates a voicing and re-measures `rel`.

### State and rendering
`S` is the single global state object (root, scale, chord, snap, top, invAll, wave, arpRate, vol). Rendering is imperative and rebuilds DOM from scratch: changing root/scale calls `renderScaleTab()` (keyboard hint, keyboard, scale strip, chips, degree cards, progressions, related keys, ear trainer) plus `fillMelodyProg()`. Changing the chord shape only re-renders chips + degree cards. `setKey(root, scaleId)` (global controls) is the shared path for every key change that does not come from the header selects (finder, related-keys chips): it re-parses the progression, refills the header, re-renders the Scale tab, the Melody Lab progression and the finder, and saves. `$`/`$$` are `querySelector` shorthands.

**Persistence (url state + undo section).** `appState()` collects the key and header controls (`r s w a`, plus `top`, `inva` and the piano octave `ko`), every Melody Lab control (`MCTL`, keyed by element id without the `m`; `ctlAlias` renames `progtext` → `prog`), the seed and the pattern (`pat`, from `encodeCells`: `.` rest, `-` hold, two base-36 chars per note, `_vv` slide), plus `bpat` / `dpat` for hand-edited bass and drums, into one object. `writeState()` puts it in the URL hash via `history.replaceState` and in localStorage (`LS_KEY`); `saveState()` is the debounced version and runs at the end of `renderPattern()` and on every control change. Init reads the hash, then localStorage (`readState`), applies the globals before `fillGlobal()` (`applyGlobalState`) and the melody controls after `fillMelodyProg()` (`applyMelodyState`), then restores the pattern (`restorePattern`) or generates from the seed. **Every new control must be added to `MCTL` (or `appState()`)** so links and reloads restore it. The finder's note set, MIDI access and the ear trainer's options/scores are deliberately not in the link (the ear trainer keeps its own localStorage key). Undo/redo (`MEL.hist` / `MEL.redo`) hold JSON snapshots `{cells, bass, drums, seed, dirty, sel, prog}`; call `pushUndo()` before any mutation of the pattern, and `applySnap` restores a snapshot (chords are re-derived from `prog` and the key).

### Audio
`audio()` lazily creates one `AudioContext` and the chain `voice → gain → compressor → lowpass → master → destination`, and builds the three pulse waveforms (`pulse50/25/125`) as `PeriodicWave`s from a Fourier series of the duty cycle. `voice(midi, opts)` is the tonal synth primitive — envelope, optional glide (`glideTo/glideT`), optional delayed vibrato (`vib`), per-voice `wave` override, optional `ramps` list for legato slides. `noise(opts)` is the second primitive: a looping one-second buffer filled by a 15-bit LFSR (deterministic, NES-style), optional `hp` high-pass / `bp` band-pass (+`q`), exponential decay over `dur`. `kick(opts)` is a triangle with a 180→42 Hz pitch drop plus a noise click. All three schedule at `t` and register their sources in `live[]` so `stopAll()` can cut them; demos call `stopAll()` first. `playNote`, `playChordSim`, `playArp` wrap `voice`; `playArp` cycles chord tones at `S.arpRate` notes/sec (the chip-arp trick itself). All scheduling uses AudioContext time via the `t` option — never `setTimeout` for note timing.

### Scale tab

**Keyboard, QWERTY piano and MIDI (keyboard section).** `renderKeyboard` draws C3–B5 (`KB_LOW`..`KB_HIGH`), marking scale notes, the root and (in finder pick mode) `.pick` keys. `hitKey(m, gain)` is the one path for pointer, computer keyboard and MIDI: `playNote`, `lightKey` (`.lit` for 220 ms) and, in pick mode, `finderToggle`. `KEYMAP` maps physical keys (`e.code`, so non-US layouts work) to offsets in the FT2 / OpenMPT layout (lower row Z…/ = 0–16, upper row Q…P = 12–28); `KBD.base` (48/60/72, moved by `[`/`]`, URL key `ko`) is the note under Z. The keydown handler only acts on the Scale tab, outside INPUT/SELECT/TEXTAREA, without Ctrl/Alt/Cmd and not on key repeat, so it never overlaps the Melody Lab editing keys, the undo keys, the Space handler or the Ear keys. `renderKbHint` writes the keys/octave/MIDI line into `#kbHint`. Web MIDI is opt-in: `#midiBtn` is unhidden only when `navigator.requestMIDIAccess` exists; a click requests access (no sysex), `midiAttach` hooks `midiMsg` to every input (again on `statechange`) and puts the input count on the button and the names in the hint (device names go through `textContent`); note-on with velocity > 0 on any channel plays through `hitKey` with a gain of .25–1 from the velocity, note-off is ignored. MIDI works on every tab.

**Degree cards and top note (chord chips + degree cards section).** `renderChordChips` / `renderDegrees` draw the shape chips and one card per scale degree from `fitChord`. `S.top` (pitch class or null) and `S.invAll` drive the top-note view: `fillTopSel()` rebuilds `#topSel` from the scale notes, and `renderDegrees` builds every card's inversion list eagerly (`buildInv`, which returns whether a row's top note matches) when either is set, marking the matching row `.hit` and cards without a match `.dim`. Both are in the URL state (`top`, `inva`).

**Related keys.** `relatedKeys()` (state section) returns `same` = every other root × scale with the identical pitch-class set (relative keys and modes, whole-tone transpositions, harmonic minor ↔ Phrygian dominant) and `par` = the `PARALLEL` partner on the same root (major ↔ natural minor, major ↔ minor pentatonic, blues ↔ major blues). `renderKin` (from `renderScaleTab`) draws them as chips in `#scaleKin` under the scale title, hidden when there are none; each chip calls `setKey`.

**Progressions row (progressions section).** `renderProgs` lists `PROGS` plus *Your progression* (the Melody Lab text) as playable rows built from `fitChord` / `chordAt`.

**Finder (finder section).** `FIND = {midis, pick, more}` holds the entered note set (in entry order; the lowest note decides the inversion). `parseFinder(text)` accepts offsets (relative to C-4), bare note names (stacked upward from C-4, flats accepted via `FLATS`) or app-style names (`parseAppNote`, `C-4` = 60; not the IT-shifted `parseNoteName`). `identifyChord(midis)` compares the pitch-class set with every `CHORDS` shape on every root (exact hits with the inversion index, plus near misses differing by one note). `scaleMatches(pcs)` is the containment loop (every root × `SCALES` holding the set, each with its `unused` notes); `fitsIn` orders it current key first for the chord pane's *Fits in* list, which is shown only when a chord was identified and labels each entry with `degreeLabel` (roman/degree of the chord root); `rankScales(pcs, midis)` orders it for the scale pane: fewest unused notes, then a root equal to the first / the lowest entered note, then `POP` (major, natural minor) before `SCALES` order. `renderFinder` draws the chord pane and calls `renderScaleFinder`, which lists up to 20 matches with the mood line and a *Use* button (`FIND.more` shows all; it resets when the note set changes). *Set key*, *Use* and the related-keys chips all call `setKey`. Pick mode: `pointerdown` on a key calls `finderToggle`; `markPicks` re-marks after re-renders.

### Melody Lab (melody lab section)
State in `MEL`. Generation is seeded: `generateMelody(seed)` reseeds `RNG` (mulberry32 from `makeRng`) and every random choice goes through `rnd`/`chance`, never `Math.random`, so seed + settings reproduces the melody, bass and slides; `MEL.seed` is shown in the Seed field. A pattern is a flat array of 16 cells per bar, each `{type:'note', midi, len}`, `{type:'hold'}` (note still ringing) or `{type:'rest'}`; displayed as hex row numbers like a tracker. Generation per bar: pick a rhythm template from `RHY[density]`, then `walkPitch` chooses pitches — chord tones on strong steps (0/4/8/12), mostly stepwise motion, occasional leaps, from that bar's pool. Bar chords come from the progression. `phrasePlan(bars)` returns per bar `{gen | copy | vary:{of, amt}, cadence}` for 1–8 bars (4-bar groups are A B A B′, 2 bars = A A′, 1 bar = cadenced; later full groups repeat A B A and end on a fresh cadence bar; remainders copy and cadence); `varyBar` rerolls a fraction of onsets and, with `cadence`, pulls the last note to root or fifth. `scheduleMelody` schedules one whole loop iteration (lead + every other column's `play` hook); looping re-schedules via a `setTimeout` fired just before the iteration ends, while a `requestAnimationFrame` tick highlights and auto-scrolls the current row. Space toggles play on the Melody tab only.

**Progressions.** The typed text in `#mProgText` is the source of truth (`PROG.text`; `PROG.specs` is the parse cached per scale, cleared with `PROG.specs=null` on a scale change). `parseProg(text, {wrap})` → `[{tok, deg, acc, chord}]` or `{error}`: digits are 1-based degrees that snap (`chord:null`); roman numerals force major/minor by case; suffixes map through `SFX` to a `CHORDS` id (lower-case roman + `7`/`6` → `m7`/`m6`); `b`/`#` set `acc` ±1 and default to major; `-` repeats; max 8 chords, degrees must be < L unless `wrap`. `chordAt(spec)` picks `fitChord` (snapped triad) or `fitChordRaw`. `currentProg()` never fails: an invalid text for the current scale falls back to the wrapped parse, then to `1 4 5 1`. `setProgression(text, {rechord})` parses, marks the field `.bad` on error (keeping the last valid text), syncs the preset select, re-renders the Scale tab's *Your progression* row, and with `rechord` rebuilds `MEL.chords`, bass and arp under the existing melody (pushing an undo snapshot when the chords of an existing pattern change). `barChord(b)` wraps `b % specs.length`. Per-bar note pools come from `barPool(chordF)` = scale notes across the range plus that bar's chord tones, so borrowed-chord tones are reachable on strong steps. The URL key for the text is `prog`.

**Columns.** Every pattern column is an entry in `COLS` (`id`, `label`, `short`, `cells()` accessor, CSS class, widths, `fx` flag for a slide/effect sub-column, `edit`, `toggle` checkbox selector, `noteOff`, optional `text(cell)` renderer, and a `play(cells, t0, stepDur)` hook). `renderPattern` builds the header (IT/SWM buttons per column), the grid template (`--pcols`) and every row from it; `exportColumn`, the plain-text dump in `copyMelody`, the `no-<id>` mute classes and the non-lead playback in `scheduleMelody` iterate it. The lead column keeps its slide-merging voice logic inline. Adding a column means adding an entry plus its generator and, if it is editable, its `pat`-style state encoding.

**Arp column.** `MEL.arp` is the chord channel: per bar, row 0 is `{type:'note', midi, len:16, arp:[x,y]}` and rows 1–15 are `{type:'hold', arp}`; every row carries `arp` because the tracker's `Jxy` only acts on rows that have it. `genArp(chords, voicing)` builds it from the bar chords an octave below the lead register (`invert()` for 1st/2nd; `auto` picks, per bar, the inversion in the octave below/this/above whose top note is nearest the previous bar's, with the lowest note kept between a fifth below and an octave above the chord root). `regenArp()` re-derives it from `MEL.chords` and `#mVoice`; it is derived data, so it is not in undo snapshots or the URL. `arpCmd(arp, row)` renders the IT command (`J`+two hex nibbles; 4-note chords alternate `J<x><y>`/`J<y><z>` by row parity, offsets above 15 fold down an octave). Export: IT writes the note on row 0 and `Jxy` on all rows; SW writes `07nn` (SID-Wizard chord select) on the note row, `nn` from `arpChordIndex()` (first-appearance order), and `exportColumn` lists the chords in the message. Playback goes through the column's `play` hook (`playArp` on `pulse125`, gain .20).

**Bass column.** `MEL.bass` is a parallel cell array in the same format (the octave-bass figure, built from the bar chords by `genBass`); it is data, not improvised at schedule time, so it can be edited and exported.

**Drums column.** `MEL.drums` cells are `{type:'note', drum:'K'|'S'|'H'|'O', len:1}` or rests (no holds). `DRUMS` is the kit (`tag` shown in the cell, `ins` = exported instrument number 1–4, `play(t, gain)`); `DRUM_PATS[style]` lists the steps per drum for one bar plus `ghost` candidates for an occasional extra kick; `DRUM_FILLS` replace the end of the last bar when there is more than one bar. Placement order is hat, open hat, kick, snare, so the snare wins a shared step (one noise channel). `genDrums(bars, style, seed)` uses its **own RNG stream** derived from the seed, so drums depend only on seed, style and length and restore identically from a link without being stored; `regenDrums()` is called wherever the pattern is (re)built. Export writes `C-5` with the instrument field `01`–`04` (`noteOff:false`, so rests never become `===`). The column's `text` hook renders the tag instead of a note name.

**Editing.** `MEL.sel = {col, i}` is the selected cell (class `.sel`); clicking an editable cell selects and auditions it, double-click toggles rest/note. `editCell(action, arg)` is the single mutation path for `nudge` (`{dir, octave, semi}`), `reroll`, `rest`, `note` (rest → chord tone, hold → split at that row), `toggle`, `longer`, `shorter` and `slide`; it snapshots for undo first (and pops the snapshot when nothing changed), re-slides the melody neighbours, marks `MEL.dirty.bass` / `MEL.dirty.drums`, auditions and re-renders. `poolFor(col, i)` picks `barPool` for the melody and `bassPool` (scale + chord tones from C1 to just under the root) for the bass; drums cycle `DRUM_ORDER`. The key map lives in a `keydown` handler next to `editCell` and only runs on the Melody tab with a selection and focus outside inputs; `moveSel` handles arrows/Tab across `COLS.filter(c=>c.edit)`. Dirty columns are kept by `setProgression`'s re-chord (bass) and encoded in the URL as `bpat` (cells codec) and `dpat` (`encodeDrums`: one char per row, `KSHO.`); Generate and a drum-style change clear the flags.

**Slides (tone portamento).** `#mSlide` (Off/Some/Lots) is a *generation* option: `placeSlides()` runs as a post-pass over the finished cells and sets `slide: vv` on note cells (peak of the bar, cadence note, leaps ≥4 st, and for Lots some stepwise moves; never on step 0, after a rest, or on a 16th); slides are copied from source bars to pure copies. `vv` is a SID-Wizard `03vv` speed derived by `slideVal()` from the interval and the note length at the current BPM (`slideSecs()` is the forward formula); it renders as an amber `3xx` fx column. `#mHearSlide` is the *playback* A/B toggle: with it on, `scheduleMelody` merges a note and the following contiguous `slide` notes into one `voice()` call with a `ramps` list (linear-in-Hz frequency ramps, no retrigger); with it off every note is voiced separately.

**Clipboard export.** `exportText(cells, 'it'|'swm', col)` writes a column in the OpenMPT (`ModPlug Tracker  IT`, 11-char cells) or DUET SID-Wizard (`DUET SW`, 9-char cells) clipboard text; the header buttons call `exportColumn(col, fmt)`. Conventions: note names are shifted one octave (`itName`) because IT calls middle C `C-5` while the app shows `C-4`; the first rest row after a note becomes `===` (note-off) in IT only; the stored SID-Wizard `slide` value is written verbatim as `03xx`, and converted for IT with `itSpeed()` assuming speed 6 and tempo = BPM (`Gxx` = xx/16 semitone per tick).

**Import (import section).** `parseTracker(text)` recognises the header (`ModPlug Tracker …`, anything ending in ` IT`, ` XM`, or `DUET SW`/`DUET SID`), splits each `|` group into a channel and reads the cell fields at fixed widths (11 for IT/XM: note ins vol fx; 9 for SW: note ins fx par); it returns `{fmt, rows, channels:[events], ignoredFx}` where an event is `{note, off, ins, porta}` (`note` already shifted down an octave via `parseNoteName`; `===`/`^^^`/`~~~` set `off`; `porta` is `{xx}` for IT `Gxx` / XM `3xx` or `{sw}` for `03xx`). `eventsToCells(events, fmt, kind)` turns a channel into app cells (empty after a note = hold, `off` or empty after silence = rest), pads to whole bars, caps at 8 bars, derives `len`, and converts portamento to a `slide` value (SW verbatim; IT/XM via `slideVal(semi, 40·semi/(bpm·xx))`, the inverse of `itSpeed`). Drums map instrument 1–4 to `DRUM_ORDER`, else pitch class C/D/F#/A#. `importText(text, colId)` applies channel 0 to the target column: melody import replaces cells, bars and chords (bass/drums regenerated when the length changes or they are not dirty) and calls `harmonize({quiet:true})`; bass/drums import fits to the pattern length and sets the dirty flag; it snapshots for undo and reports what was ignored. `importColumn(colId)` tries `navigator.clipboard.readText()` and falls back to the `#mPasteBox` textarea. Input is capped at 64 KB and never evaluated.

**Harmonize (harmonize section).** `harmCandidates()` = the snapped triad on every degree (`tok` = degree number) plus, in 7-note scales, the snapped 7th when `chordLabel` maps it to a `CHORDS` shape the syntax can name (`tok` = degree + `SFX_OF[id]`, tier 1, −1.5 penalty). `harmBarScore(b, cand)` weighs chord tones (steps 0/8 ×3, 4/12 ×2.5, other 8ths ×1.2, 16ths ×.8, times note length capped at 4), penalises non-chord tones (more on strong steps), rewards a bar starting on the root, and, when `MEL.dirty.bass`, adds bass-note weight (root +4, fifth +1, other chord tone +.5, else −2). `harmTrans(a, b, bar, bars)` adds common tones (+.5 each), root motion by a fourth/fifth (+.8), a repeat penalty, tonic bonuses on the first (+1.5) and last (+2.5) bar and a dominant bonus on the second-to-last (7-note scales). `harmonize()` runs a Viterbi pass and writes the chosen tokens into the progression text via `setProgression`, so chords stay derived from the text. `harmAlternatives(b)` ranks candidates for one bar against its current neighbours; `showAlternatives` renders them as a popover in the Chord column and `chooseChord(b, tok)` rewrites that bar's token (`barTokens()` expands a short progression to one token per bar first, and re-fills following `-` tokens).

### Ear trainer (ear trainer section)
`EAR_MODES` is a table of four modes (`int`, `chd`, `scl`, `deg`), each with `answers(opts)` (the chips: `v` value, `l` label, `s` small text), `make(opts)` (a question) and `play(q, t, v)` (schedules on AudioContext time and returns the end time; `v` overrides the answer so a wrong answer can be replayed after the right one). `EAR_SETS` holds the interval / chord / scale subsets, `EAR_OPTS` the option chips per mode. `EAR = {mode, opts, stats, q, answered, last}`; `earNew` / `earReplay` / `earAnswer` are the flow, `earStat(mode)` the per-mode `{ok, n, streak, best}`, `renderEar` redraws everything from state. Mode, options and stats persist in localStorage under `EAR_LS` (`earSave` / `earLoad`, validated on load) and deliberately not in the share link. Questions use `Math.random`: they are outside the seeded generation. The key handler (digits `1`–`9` `0` `-` `=` = semitones in Intervals, the degree in Degrees, the n-th chip otherwise; `R` replay; `Enter` next, ignored on a focused button) runs only on the Ear tab, outside inputs, without modifiers. `renderScaleTab` calls `renderEar`, so Degrees follows the header key and a pending question whose degree no longer exists is dropped.

### Learn cards and demos (demos, techniques content, theory content, learn renderer sections)
`renderLearn(el, items)` draws `TECH` / `THEORY` as `.lcard`s (first one open) and prepends a "Hear it" button when the item has a `d` key. `DEMOS` is an object of named functions; every demo calls `stopAll()` first and schedules with `voice` / `playArp` / `DRUMS[x].play` on AudioContext time. Interval chips (`[data-int]` buttons from `intervalTable()`) play the interval melodically then harmonically via a delegated click handler. Prose voice: short, direct, tracker-first, semitones only, no flats in note names.
